A personal research and engineering project: a guarded local operator around the
tools I already use — Claude Code, Codex, GitHub, local repositories, terminal
sessions, and strict proof gates.

## What it is

XEMA is not a public SaaS agent and not a black-box automation toy. It is a
private, local-first orchestration layer designed to help me work on SUAVE with
more discipline:

- **Codex as verifier / mentor** — planning, review, risk classification, GO /
  NO-GO decisions.
- **Claude Code as builder** — scoped implementation work under explicit rules.
- **XEMA as operator** — eventually coordinating context, prompts, sessions,
  safety gates, reports, and memory.

The current focus is foundations: source-of-truth docs, safety primitives,
bounded execution, auditability, and specifications before higher autonomy.

## What it is built to protect

- The right repository.
- The right branch.
- The right scope.
- No accidental secret exposure.
- No provider or production mutation without a human decision.
- No autonomous loop without explicit gates.
- No false "green" when proof is missing.

## Engineering direction

- **Local-first.** Runs against my real development machine and real workflows.
- **Windows-first.** Built around the environment I actually use.
- **Safety-first.** Permission policy, repo guard, Job Object containment, kill
  switch, redaction, and audit logs before broad tool use.
- **Proof-first.** Tests, CI, source-of-truth gates, and explicit proof tiers.
- **Human-gated.** Strategy, merge, secrets, providers, staging, production, and
  irreversible actions stay human-owned.

## Why it matters

The goal is not to replace judgment. The goal is to build a disciplined local
assistant that can help coordinate serious engineering work without turning into
an uncontrolled script pile.

The project is private while the safety model, architecture, and operating
contract mature.
